## 1. Goal metric: census all-layers, and the encoder_slot constraint

Wave 4 is measured by **`RULES-COVERAGE all-layers`** — a name counts only when registry, mechanics,
core and encoder all know it, in every system it appears in. At `ba58c9d4`:

| layer | covered |
|---|---|
| registry-primitive | 444/452 |
| mechanics-entry | 449/452 |
| core-ported | 376/450 (STAMPED 19, PARTIAL 12, MISSING 28, GRANT-MISSING 15) |
| **encoder-slot** | **185/452** |
| **all-layers** | **165/452** |

**The encoder is the binding constraint, and it is hard-capped.** Measured at this head:

- **207 names** are registry + mechanics + core PORTED and fail all-layers on `encoder_slot` alone.
- The all-layers ceiling with today's core is **372** against today's 165: the gap is 207 encoder
  slots, not port work.
- `data/encoder_rule_vocab_v1.json` (v5) is **append-only** and the **unit band is full: 200/200**
  (its own `comment_v5` says so; the weapon band has room, 25/100). The 207 cannot be closed by
  appending — it needs a v6 unit band, which changes the board row width and invalidates every
  recorded corpus and every trained net that reads it.
- Of wave 4's 23 PORT names, **only 4 hold a unit slot in every system they appear in**:
  `Melee Slayer`, `Aircraft`, `Quick Readjustment`, `Sturdy`.

**So wave 4 has two tracks and two numbers, and neither stands in for the other:**

- **Track F (families, this plan): `core_ported` 376 → 395 (+19), `all-layers` 165 → 169 (+4).**
  That +4 is the honest ceiling of the whole family programme.
- **Track E (encoder vocabulary): a maintainer decision, not a port** — see §8. Until it is taken,
  all-layers is capped at 169 no matter how many families ship.

## 5. Serial merge order (pre-agreed, one PR in flight at a time)

Wave 3 rebased 6-8 times per PR because family PRs ran concurrently into the same append points.
Wave 4 merges **serially**:

1. **W4-0 `core-rules-epoch-7`** — `EPOCH_7_TABLE_RULES: u32 = 7` + `CURRENT_RULES_EPOCH = 7`; no
   rule change, no census delta. First PR of the wave, per the epoch rule.
2. **W4-1 `rules-wave4-registry-only`** — F3. Zero core diff; the only PR allowed to touch
   `assets/solo/rules_mechanics_*.json` before W4-4. Claim: registry +4, mechanics +1, all-layers +1.
3. **W4-2 `rules-wave4-boostbases2`** — F1. Claim: core_ported +6.
4. **W4-3 `rules-wave4-condap`** — F2, largest and riskiest, so it goes after the two cheap ones.
   Claim: core_ported +8, all-layers +1; ships 6 names if the `Melee Slayer` text check fails.
5. **W4-4 `rules-wave4-renames`** — F4. Touches the registry JSONs again; after W4-1 by construction.
   Claim: core_ported +2, registry +0, mechanics +0 (F4 corrections above: #734 and #746
   already registered both names).
6. **W4-5 `rules-wave4-singles`** — F5, including the Sturdy registry remap. Claim: core_ported +3,
   all-layers +2.
7. **W4-6 `docs-rules-wave4-accounting`** — claimed vs proven per PR, the way wave 3 closed.

The order is a *policy*, not a dependency chain (only W4-4 truly depends on W4-1): it keeps one PR
at a time in the shared files. A second PR may be prepared, but not merged, while another is gating.

## 6. Per-family file layout — no two PRs touch the same section

The behaviour-neutral refactor that makes this possible ships first (`rules-wave4-shape`). After it:

| what a family PR adds | where | shared lines it touches |
|---|---|---|
| tests | **new file** `core/nml-core/src/tests/<owner>/<family>.rs` | one `mod <family>;` line in that directory's `mod.rs`, alphabetically placed |
| census param row | `CONSUMED_PARAM_KEYS` registry row, **alphabetical by primitive** | one row at its own alphabetical position, not at the tail |
| registry data | `assets/solo/rules_mechanics_<system>.json` | serialised by the merge order (§5), never concurrent |
| core resolver | the seam file that already owns the read (`unit.rs`, `dice.rs`, `sim.rs`) | one function + one call site; **no widened signatures** |

- A family's tests go in **its own file**; appending to another family's file is a review reject.
- The `mod` list and the census rows are kept **sorted**; the census asserts its own sort order at
  import, so an out-of-order or duplicate row fails loudly instead of silently overwriting.
- A PR that must touch a second family's file has found a shared seam: say so in the PR body.

## 7. The brief rules that stay (unchanged from wave 3)

1. **RED first.** A named test that fails on the branch before the port and passes after. A green-only
   branch is not evidence. State the test names in the PR body.
2. **Predicted census delta per name.** The PR body lists every name it claims and the layer each one
   moves. The gate re-measures; claimed ≠ proven is a defect, not a rounding difference.
3. **Aura and base in ONE PR.** Since #728 the census follows the grant: an aura whose base is
   unported is GRANT-MISSING, and porting a base flips its aura for free. Splitting them wastes the
   second half of the delta and leaves a dead chain on the table.
4. **Gate constant `EPOCH_7_TABLE_RULES`.** Production reads the frozen constant, never
   `CURRENT_RULES_EPOCH`. The epoch bump is the **first** PR of the wave (W4-0), not the last.
5. **No widened signatures.** A family may not change a shared function's parameter list; that is
   what forced wave-3 rebases across unrelated PRs.
6. **The census follows the grant, and a `CONSUMED_PARAM_KEYS` row needs a reader.** Adding param
   keys with no resolver reading them flips names to PORTED while nothing runs — bug #489's exact
   shape. If there is no reader, the honest verdict is STAMPED.
7. **One family = one PR, ≤ 120 production lines.** Over the cap, split; `SIZE_OK=1` is the
   maintainer's call, never the job's.
8. **Replay fidelity is an absolute floor**, not a comparison: `replay_exact` must not drop. Gate by
   the corpus recording sha; the epoch a record needs is the frozen constant of its own wave.

## 8. Open decisions for the maintainer

1. **The encoder track (§1).** All-layers is capped at 169 until the unit band grows past 200. A v6
   vocabulary invalidates recorded corpora and trained nets. Three options: (a) fund v6 and a
   re-record, (b) declare all-layers capped and track `core_ported` as the wave metric, (c) reclaim
   the three dead unit slots from v5 — cheapest, worth +3 at most, and silently remaps meaning for
   corpora recorded under v4. Recommend (b) for wave 4 and (a) as its own wave.
2. **Melee Slayer's classification (§2, F2).** 27 occurrences, the least certain PORT in the map.
   Read the text before W4-3 is sliced.
3. **Seam 2 (§3).** It is worth 11 names, not 7. Does that change the §6 "documented NO" default of
   the Utility Buff seam document?
4. **Sniper REMOVE (§4).** Rule or book-hygiene marker? If a marker, it goes N/A like `Unique` and
   the universe drops to 451.
5. **Which coverage number is public.** `core_ported` 376 and `all-layers` 165 tell different
   stories. Follow-the-grant already moved the honest core number down by 20 on a night when the
   work went forward; the same will happen again if all-layers becomes the headline.
