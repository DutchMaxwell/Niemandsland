## The three rows I would fix first
1. Morale (TABLE-ONLY) — core never reads the Morale primitive at all (morale math sums only Banner-family morale_bonus, unit.rs:1651-1672/1829-1831), while the table adds the rating to every morale test (solo_controller.gd:5642-5653 -> main.gd:8586). A player in core-driven games sees rated-morale units rout where the table holds them; it also silently skews any parity/planner expectations. Fix: read the Morale-primitive rating into the core morale test.
2. Rending when Shooting Aura (TABLE-ONLY) — the core stamps the entry but consumes nothing: it is absent from WAVE2_UTILITY_BUFF_RULES (unit.rs:3009-3022), no code reads the granted "Rending when Shooting" name, and the granted record never reaches sim.rs:2477/2656. Table-side it works end-to-end (main.gd:8132, ai_ev.gd:330-334, main.gd:7104). A player loses the shooting-half AP(4) on wound-6 and the Regeneration bypass whenever the core resolves the fight. Fix: read the aura's grants_rule onto the bearer's shooting profiles at epoch >= EPOCH_7.
3. Protection Feat (DERIVES, flagged risk) — its uses_per_game=1 is kept out of the core's flat stamps (the once-per-game precedent, unit.rs:2877-2879), but the table's Regeneration fold applies ignore_target from every Regeneration-primitive entry unconditionally (main.gd:6747-6750). If the feat's once-per-game limit is meant to gate the 5+ regeneration window too, the table over-credits it every activation; worth a targeted check and either a gate or a census note.
