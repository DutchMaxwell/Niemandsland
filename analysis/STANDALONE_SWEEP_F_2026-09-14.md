## The three rows I would fix first

1. **Great Sergeant (DIVERGES)** — the printed "5 or 6" is dead data in BOTH layers
   (unit.rs:5124-5128 says so in prose): a player rolls a 5 with Great Sergeant and gets no bonus
   hit, every time, silently. One param read (`surge_low`, already plumbed for Ferocious/Lucky
   Boost at main.gd:4534) fixes it.
2. **Grounded Speed (DIVERGES)** — the table's band pass
   (movement_range_controller.gd:152-163) applies +2"/+4" unconditionally because it only sees the
   Fast primitive's params; the "most models within 1\" of terrain" condition never gates the
   visible move rings, while the core gates it from epoch 7. The player notices extra speed in the
   open — and the two layers disagree with each other.
3. **Fortified Aura, aofs/gff spelling (DIVERGES)** — `lost_if_bearer_killed` and `max_picks` are
   read by nobody (unit.rs:1399-1410 reads only the over_in gate): kill the aura bearer and the
   unit keeps AP(-1) on every save for the rest of the game. The aof spelling (Aura Channel +
   grants) is unaffected, so the same rule name behaves differently per system.

Honourable mention: **Havocbound Boost (CORE-ONLY)** — the table's generic conditional-AP pass
(main.gd:7027/7043) keys on `condition`/`gate`, which the Boost entry does not carry, so the
printed "always AP(+1)" never fires on the table's own dice; the core states the leg by name
(unit.rs:5224-5228). A one-line `always` check in `_solo_conditional_ap_parts` would close it.
