# The ruin-town dressing kit forge

The forge builds the **dressing kit** of a generated ruin town: the authored modules (house
panels, gables, roofs, chimneys, ruin tier faces, town walls, towers, lamps, plots, refuse,
vegetation) that `scripts/boardgen_dress*.gd` draws over the board layout. The gameplay truth is
the layout grid; these modules only dress it. The contract between the two sides is
`assets/ruintown_dress.json` (one entry per module with its numbers, plus the `materials`,
`ground`, `sets` and `licence` blocks), described in
[ADR 0004](../../docs/adr/0004-dressing-materials-and-kit-manifest.md).

Nothing here runs in the game. The scripts are a tool that runs at build time: they generate the module GLBs
and the manifest, and they check both against the kit's honesty rules.

## Files

| File | What it does |
|---|---|
| `dress_kit.py` | Entry point. `--manifest-only` writes the nominal manifest without Blender; otherwise it runs the forge. |
| `kit_table.py` | The module table (name, family, bounds, materials, tags), the material and ground tables and the manifest writer. Pure Python. |
| `kit_build.py` | The Blender builders of the house set, the shared geometry helpers and the forge loop (export + checks). |
| `kit_k2.py` … `kit_k5b.py` | The builders of the further batches: ruin tiers, town walls and towers, lamps / landmarks / plots, refuse, vegetation. |
| `check_kit.py` | The forge checks: declared openings, triangle caps, proud limits, honest heights, no embedded images, tiling ends. Pure Python. |
| `kit_sheet.py`, `kit_k*_sheet.py`, `compose_sheet.py` | Optional preview sheets (Blender renders + a PIL compose step). Preview only, never shipped. |

## Requirements

- **Blender 5.1.2** for the full forge (headless is enough).
- **Python 3** for `--manifest-only` and for `check_kit.py`; no third-party packages.
- Pillow only for `compose_sheet.py`.

## Build the GLBs

From the repository root:

```bash
blender -b --factory-startup --python tools/kit_forge/dress_kit.py -- build/kit_forge
```

The output directory is the argument after `--`; without it the forge writes to
`build/kit_forge/` (the `build/` tree is git-ignored). The forge writes one `<module>.glb` per
module and, last, `ruintown_dress.json`. It refuses the export on any failed check and prints
`CHECK_FAIL` lines for every failure.

The **built GLBs are not stored in git**: they are build artefacts, generated on demand. The
manifest is the tracked half of the contract; copy the freshly built `ruintown_dress.json` to
`assets/ruintown_dress.json` when the module table changes.

To write only the nominal manifest (no Blender, every module still a stub):

```bash
python3 tools/kit_forge/dress_kit.py --manifest-only
```

## Check a built kit

```bash
python3 tools/kit_forge/check_kit.py build/kit_forge
```

This re-reads every GLB against the manifest: openings, triangle caps, proud limits, honest
heights, no embedded images or unknown material names, and the tiling match at both ends of a
face module. It exits non-zero and names each failure.

## Preview sheets (optional)

```bash
blender -b --factory-startup --python tools/kit_forge/dress_kit.py -- build/kit_forge --sheet=K1
python3 tools/kit_forge/compose_sheet.py build/sheets/rows_k1 build/sheets/sheet_k1.jpg
```

The preview shading reads local copies of the texture sets, which are not in git. Point these
environment variables at them (the defaults are directories under `build/kit_forge/`):

| Variable | What it must contain |
|---|---|
| `NML_KIT_TEX512` | 512 px JPEG copies of the texture sets (`<set>_albedo.jpg`, …). |
| `NML_KIT_STONE_1K` | the 1k stone source (`albedo.png`, `normal.png`, `orm.png`). |
| `NML_KIT_GRASS_DIR` | the grass card source (`grass_medium_01_diff_1k.png`, `grass_medium_01_alpha_1k.png`). |
| `NML_KIT_VEG_SOURCE` | the vegetation generator source file. It is **not** part of this repository, so the vegetation modules cannot be built without it; default is `veg_kit.py` next to these scripts. |
